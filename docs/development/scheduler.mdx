---
title: Scheduler
---

SwiftlyS2 provides a scheduler service for main-thread dispatching and timer-based execution, available through <ApiRef name="ISwiftlyCore" member="Scheduler" /> (<ApiRef name="ISchedulerService" />). Every callback you hand to it runs on the game thread, so it is the way to call thread-unsafe APIs from a background flow or to delay work until later.

## Scheduling on the Main Loop

<ApiRef name="ISchedulerService" member="NextTick" /> runs a callback on the
next server tick; <ApiRef name="ISchedulerService" member="NextWorldUpdate" />
runs on the next world update phase instead:

```csharp
Core.Scheduler.NextTick(() => Console.WriteLine("Runs on next tick."));
Core.Scheduler.NextWorldUpdate(() => Console.WriteLine("Runs on next world update."));
```

Both take an `Action` and return `void`.

### Awaitable Variants

<ApiRef name="ISchedulerService" member="NextTickAsync" /> and
<ApiRef name="ISchedulerService" member="NextWorldUpdateAsync" /> take the same
`Action`/`Func<T>` overloads and can be awaited - the `Action` overloads return
`Task`, the `Func<T>` overloads return `Task<T>`:

```csharp
await Core.Scheduler.NextTickAsync(() => Console.WriteLine("Executed on next tick, awaited."));

int computedValue = await Core.Scheduler.NextWorldUpdateAsync(() => 42);
```

<Callout type="warning">
Don't pass an async callback (`Func<Task>`/`Func<Task<T>>`) to `NextTick`, `NextTickAsync`, `NextWorldUpdate`, or `NextWorldUpdateAsync` - those overloads are `[Obsolete]` and throw `InvalidOperationException`, since an async callback can resume on a different thread and break the main-thread guarantee these methods exist for. Use the plain `Action`/`Func<T>` overloads instead.
</Callout>

## Timer APIs

Every timer method returns a `CancellationTokenSource` you can cancel, and takes the callback as an `Action` that runs on the game thread.

### Tick-Based Timers

```csharp
var delayCts = Core.Scheduler.Delay(128, () => Console.WriteLine("Executed once after 128 ticks."));
var repeatCts = Core.Scheduler.Repeat(64, () => Console.WriteLine("Runs immediately, then every 64 ticks."));
var delayRepeatCts = Core.Scheduler.DelayAndRepeat(32, 64, () => Console.WriteLine("Starts after 32 ticks, then repeats every 64 ticks."));
```

Intervals for these three are `int` ticks. See <ApiRef name="ISchedulerService" member="Delay" />,
<ApiRef name="ISchedulerService" member="Repeat" />, and
<ApiRef name="ISchedulerService" member="DelayAndRepeat" />.

### Second-Based Timers

<ApiRef name="ISchedulerService" member="DelayBySeconds" />,
<ApiRef name="ISchedulerService" member="RepeatBySeconds" />, and
<ApiRef name="ISchedulerService" member="DelayAndRepeatBySeconds" /> mirror the
tick-based methods above with `float` seconds instead of raw ticks:

```csharp
Core.Scheduler.DelayBySeconds(2.0f, () => Console.WriteLine("Executed after 2 seconds."));
Core.Scheduler.RepeatBySeconds(0.5f, () => Console.WriteLine("Runs immediately, then every 0.5 seconds."));
```

<Callout type="info">
    Second-based timers are still driven by game ticks, so timing gets
    inaccurate as intervals approach a single tick (~15ms).
</Callout>

## Canceling Timers

Every timer method - `Delay`, `Repeat`, `DelayAndRepeat`, `DelayBySeconds`, `RepeatBySeconds`, `DelayAndRepeatBySeconds` and `AddTimer` - returns a `CancellationTokenSource`:

```csharp
var token = Core.Scheduler.Repeat(64, () => Console.WriteLine("Tick"));

token.Cancel(); // manual cancel
Core.Scheduler.StopOnMapChange(token); // auto-cancel on map change
```

See <ApiRef name="ISchedulerService" member="StopOnMapChange" />.

## Advanced Timers with AddTimer

<ApiRef name="ISchedulerService" member="AddTimer" /> takes a
`Func<ITimerContext, TimerStep>` and supports dynamic per-execution behavior -
e.g. changing the delay between runs or stopping on a condition. The callback
runs again only if the returned <ApiRef name="TimerStep" /> says so:

```csharp
var cts = Core.Scheduler.AddTimer(ctx =>
{
    Console.WriteLine($"Run #{ctx.ExecutionCount}");
    return ctx.ExecutionCount >= 4 ? TimerStep.Stop() : TimerStep.WaitForSeconds(1.0f);
});
```

Every run receives an <ApiRef name="ITimerContext" />, whose only member is
<ApiRef name="ITimerContext" member="ExecutionCount" /> - a `ulong` counting the
runs of that timer, starting at `0` for the first one.

| Member                                          | Signature                        | Description                                              |
| ----------------------------------------------- | -------------------------------- | -------------------------------------------------------- |
| <ApiRef name="ITimerContext" member="ExecutionCount" /> | `ulong ExecutionCount { get; }`  | Number of runs so far, starting at `0` for the first run |

<ApiRef name="TimerStep" /> is an abstract record with a private constructor, so
you always get one of the steps below from its static helpers:

| Method                                             | Signature                                     | Behavior                                                                                    |
| -------------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `TimerStep.Spin()`                                 | `static TimerStep Spin()`                     | Run again on the very next tick                                                             |
| `TimerStep.WaitForTicks(long ticks)`               | `static TimerStep WaitForTicks(long ticks)`   | Wait the given number of ticks before the next run                                          |
| `TimerStep.WaitForMilliseconds(long milliseconds)` | `static TimerStep WaitForMilliseconds(long milliseconds)` | Wait the given number of milliseconds before the next run                        |
| `TimerStep.WaitForSeconds(float seconds)`          | `static TimerStep WaitForSeconds(float seconds)` | Wait the given number of seconds before the next run (converted to milliseconds internally) |
| `TimerStep.Stop()`                                 | `static TimerStep Stop()`                     | Stop the timer, no further runs                                                             |

<Callout type="info">
    `WaitForTicks` and `WaitForMilliseconds` require an argument greater than `0`
    and throw `ArgumentException` otherwise. Since `WaitForSeconds` is converted
    to whole milliseconds, sub-millisecond values round down to `0` and are
    rejected the same way.
</Callout>

documented in the callout above only so you don't use them.
