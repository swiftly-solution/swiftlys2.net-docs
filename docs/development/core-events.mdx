---
title: Core Events
---

Core events are SwiftlyS2's own engine/framework callbacks - client lifecycle, entity lifecycle, convar and command changes, console output, server startup, tick/world update - separate from the CS2 [game events](/docs/development/game-events) system. They're exposed through `Core.Event` (<ApiRef name="IEventSubscriber" />), a set of plain C# events.

## Subscribing

Subscribe with a plain `+=`, or with `[EventListener<T>]` where `T` is the matching delegate from `EventDelegates`.

<Tabs>
  <Tab label="Programmatically">
    ```csharp
    public override void Load(bool hotReload)
    {
        Core.Event.OnClientConnected += OnClientConnected;
    }

    private void OnClientConnected(IOnClientConnectedEvent @event)
    {
        Console.WriteLine($"Client connected: {@event.PlayerId}");
    }
    ```

  </Tab>
  <Tab label="With attribute">
    ```csharp
    [EventListener<EventDelegates.OnClientConnected>]
    public void OnClientConnected(IOnClientConnectedEvent @event)
    {
        Console.WriteLine($"Client connected: {@event.PlayerId}");
    }
    ```
  </Tab>
</Tabs>

Match the delegate signature exactly - `EventDelegates.OnClientConnected` is `void(IOnClientConnectedEvent @event)`; `OnTick`, `OnWorldUpdate`, `OnSteamAPIActivated` and `OnStartupServer` take no parameters at all, so their handlers are `void ()`.

<ApiRef name="EventListener`1" /> takes no arguments and its type parameter is constrained to delegates (`where T : Delegate`); a method can carry only one of them (`AllowMultiple = false`) - use `+=` when a single method or instance has to listen to several events.

Attribute handlers are discovered on registered instances: your plugin class is registered automatically, any other class must be passed to `Core.Registrator.Register(instance)` - see [Using Attributes](/docs/development/using-attributes).

## Blocking a Client from Joining

Some events expose a settable `Result` to reject the action. <ApiRef name="IOnClientConnectedEvent" /> is the client-lifecycle one - set it to `HookResult.Stop` or `HookResult.CancelOriginal`:

```csharp
[EventListener<EventDelegates.OnClientConnected>]
public void OnClientConnected(IOnClientConnectedEvent @event)
{
    if (IsBanned(@event.PlayerId))
    {
        @event.Result = HookResult.Stop;
    }
}
```

The other events with a settable `Result` are `OnCommandExecuteHook` (only in the `Pre` pass) and the obsolete `OnEntityTakeDamage`, `OnWeaponServicesDropWeaponHook`, `OnEntityIdentityAcceptInputHook` and `OnEntityFireOutputHook`. What each <ApiRef name="HookResult" /> value does to the remaining hooks and the original call is described in [Native Functions and Hooks](/docs/development/native-functions-and-hooks#hook-modes-and-results).

## Unsubscribing

`-=` only removes a subscription added with `+=` - keep a reference to the exact delegate instance:

```csharp
private EventDelegates.OnClientConnected? _onClientConnected;

public override void Load(bool hotReload)
{
    _onClientConnected = OnClientConnected;
    Core.Event.OnClientConnected += _onClientConnected;
}

public override void Unload()
{
    if (_onClientConnected != null)
        Core.Event.OnClientConnected -= _onClientConnected;
}
```

<Callout type="info">
    The framework tears down every listener a plugin registered on hot reload or
    unload automatically - unsubscribe manually only to stop listening earlier.
</Callout>

## Hot Path Events

`OnTick`, `OnWorldUpdate`, and the obsolete `OnClientProcessUsercmds` are the hot-path callbacks - the first two fire every tick/frame, `OnClientProcessUsercmds` once per user-command batch of a client. Keep handlers allocation-free and cheap; push anything heavier to a scheduled task or a flag.

`OnTick` doesn't run while the server is in hibernation, `OnWorldUpdate` does.

## Deprecated Hook-Style Events

Several `Core.Event` members that used to be the only way to intercept a native call are `[Obsolete]` in favor of the more structured [`Core.GameHooks`](/docs/development/native-functions-and-hooks) categories - separate pre/post delegates and a richer context object instead of one generic event:

| Obsolete event                                              | Use instead                                          |
| ----------------------------------------------------------- | ---------------------------------------------------- |
| `OnClientProcessUsercmds`                                   | `Core.GameHooks.Controller.ProcessUsercmds`          |
| `OnEntityTakeDamage`                                        | `Core.GameHooks.Entities.TakeDamage`                 |
| `OnItemServicesCanAcquireHook`                              | `Core.GameHooks.Items.CanAcquire`                    |
| `OnWeaponServicesCanUseHook`                                | `Core.GameHooks.Weapons.CanUse`                      |
| `OnWeaponServicesDropWeaponHook`                            | `Core.GameHooks.Weapons.Drop`                        |
| `OnEntityStartTouch` / `OnEntityTouch` / `OnEntityEndTouch` | `Core.GameHooks.Entities.{StartTouch,Touch,EndTouch}` |
| `OnMovementServicesRunCommandHook`                          | `Core.GameHooks.Movement.RunCommand`                 |
| `OnPlayerPawnPostThink`                                     | `Core.GameHooks.Pawn.PostThink`                      |
| `OnEntityIdentityAcceptInputHook`                           | `Core.GameHooks.Entities.AcceptInput`                |
| `OnEntityFireOutputHook`                                    | `Core.GameHooks.Entities.FireOutput`                 |

The parameter interfaces of these events are `[Obsolete]` as well, so a handler that takes one of these event objects produces a compiler warning too.

## Event Reference

Each parameter interface lives under `SwiftlyS2.Shared.Events` and exposes only the fields relevant to that callback. The delegate on <ApiRef name="EventDelegates" /> has the same name as the `Core.Event` member - `OnEntityFireOutputHook` is the exception, its delegate is `EventDelegates.OnEntityFireOutputHookEvent`.

### Client Lifecycle

- `OnClientConnected` - <ApiRef name="IOnClientConnectedEvent" />: `PlayerId` (`int`), settable `Result` (`HookResult`).
- `OnClientDisconnected` - <ApiRef name="IOnClientDisconnectedEvent" />: `PlayerId` (`int`), `Reason` (`ENetworkDisconnectionReason`).
- `OnClientPutInServer` - <ApiRef name="IOnClientPutInServerEvent" />: `PlayerId` (`int`), `Kind` (<ApiRef name="ClientKind" />).
- `OnClientSteamAuthorize` - <ApiRef name="IOnClientSteamAuthorizeEvent" />: `PlayerId` (`int`).
- `OnClientSteamAuthorizeFail` - <ApiRef name="IOnClientSteamAuthorizeFailEvent" />: `PlayerId` (`int`).
- `OnClientKeyStateChanged` - <ApiRef name="IOnClientKeyStateChangedEvent" />: `PlayerId` (`int`), `Key` (<ApiRef name="KeyKind" />), `Pressed` (`bool`).
- `OnClientVoice` - <ApiRef name="IOnClientVoiceEvent" />: `PlayerId` (`int`).

### Entity Lifecycle

- `OnEntityCreated` - <ApiRef name="IOnEntityCreatedEvent" />: `Entity` (`CEntityInstance`). The entity isn't fully initialized yet - do your work on the next tick and check its validity there.
- `OnEntitySpawned` - <ApiRef name="IOnEntitySpawnedEvent" />: `Entity` (`CEntityInstance`).
- `OnEntityDeleted` - <ApiRef name="IOnEntityDeletedEvent" />: `Entity` (`CEntityInstance`).
- `OnEntityParentChanged` - <ApiRef name="IOnEntityParentChangedEvent" />: `Entity` (`CEntityInstance`), `NewParent` (`CEntityInstance?`).

### ConVar and Commands

- `OnConVarCreated` - <ApiRef name="IOnConVarCreated" />: `ConVarName` (`string`).
- `OnConVarValueChanged` - <ApiRef name="IOnConVarValueChanged" />: `ConVarName` (`string`), `PlayerId` (`int`, the client that made the change), `NewValue` and `OldValue` (both `string`).
- `OnConCommandCreated` - <ApiRef name="IOnConCommandCreated" />: `CommandName` (`string`).
- `OnCommandExecuteHook` - <ApiRef name="IOnCommandExecuteHookEvent" />: `Command` (`ref CCommand`), `HookMode` (<ApiRef name="HookMode" />), settable `Result` (`HookResult`). `HookMode` tells you whether this is the `Pre` or the `Post` pass, and `Result` can only be changed in `Pre`.
- `OnConsoleOutput` - <ApiRef name="IOnConsoleOutputEvent" />: `Message` (`string`). Callbacks run on the dedicated console dispatch thread - schedule the work onto the game thread before touching game-thread-only APIs (see [Thread Safety](/docs/development/thread-safety)).

The convar events are covered in more detail in [Convars](/docs/development/convars).

### Server and World

- `OnMapLoad` - <ApiRef name="IOnMapLoadEvent" />: `MapName` (`string`).
- `OnMapUnload` - <ApiRef name="IOnMapUnloadEvent" />: `MapName` (`string`).
- `OnPrecacheResource` - <ApiRef name="IOnPrecacheResourceEvent" />: `AddItem(string path)` adds a resource to the precache list.
- `OnStartupServer`, `OnTick`, `OnWorldUpdate`, `OnSteamAPIActivated` - no event object, the handler takes no parameters.

### UI

- `OnCustomHudClicked` - <ApiRef name="IOnCustomHudClickedEvent" />: `PlayerId` (`int`), `CustomHudLayout` (`CCSCustomHudLayout`), `ButtonId` (`string`). See [Custom HUD](/docs/development/custom-hud).

## ClientKind and KeyKind

Two enums are carried by event objects rather than configured:

<ApiRef name="ClientKind" /> is reported by `IOnClientPutInServerEvent.Kind`:

| Value     | Number |
| --------- | ------ |
| `Player`  | `0`    |
| `Bot`     | `1`    |
| `Unknown` | `2`    |

<ApiRef name="KeyKind" /> is reported by `IOnClientKeyStateChangedEvent.Key`:

`Mouse1`, `Mouse2`, `Space`, `Ctrl`, `W`, `A`, `S`, `D`, `E`, `Esc`, `R`, `Alt`, `Shift`, `Weapon1`, `Weapon2`, `Grenade1`, `Grenade2`, `Tab`, `F`
