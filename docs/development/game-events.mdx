title: Game Events

<Callout type="warning">
    Game events are a legacy Source 2 mechanism and Valve has been retiring them
    over time - some events no longer fire in current CS2 builds. Prefer [Game
    Hooks](/docs/development/native-functions-and-hooks) or [Core
    Events](/docs/development/core-events) when an equivalent exists.
</Callout>

SwiftlyS2 generates a strongly-typed interface for every CS2 game event, exposed through the plugin-scoped `Core.GameEvent` service (<ApiRef name="ISwiftlyCore" member="GameEvent" />, type <ApiRef name="IGameEventService" />).

## Firing Events

`Fire` broadcasts to every player, `FireToPlayer` targets a slot, `FireToServer` stays server-side. Each has an overload taking an `Action<T>` to configure the event before it is sent, and an async counterpart (`FireAsync`, `FireToPlayerAsync`, `FireToServerAsync`, all returning `Task`) for off-main-thread use - the sync overloads are thread-unsafe, see [Thread Safety](/docs/development/thread-safety).

```csharp
// To everyone, with an optional configure callback
Core.GameEvent.Fire<EventShowSurvivalRespawnStatus>(@event =>
{
    @event.LocToken = "survival_respawn_status";
    @event.Duration = 5;
});

// To one player slot
Core.GameEvent.FireToPlayer<EventShowSurvivalRespawnStatus>(0, @event =>
{
    @event.LocToken = "private_status";
});

// Server-side only
Core.GameEvent.FireToServer<EventShowSurvivalRespawnStatus>();

// Off the main thread
await Core.GameEvent.FireAsync<EventShowSurvivalRespawnStatus>();
```

<Callout type="warning">
    The event instance passed to a configure callback is only valid for that
    callback's duration - don't stash and read it later.
</Callout>

Every event has a settable `DontBroadcast` flag - set it inside the configure callback to build the event without broadcasting it to clients.

## Hooking Events

Register hooks by attribute or manually through the service, in `Pre` (`0`) or `Post` (`1`) mode (<ApiRef name="HookMode" />) - `Pre` runs before the game processes the event, `Post` after. Handlers match the <ApiRef name="IGameEventService" member="GameEventHandler" /> delegate, `HookResult (T eventObj)` for the event type they take, and return <ApiRef name="HookResult" />:

<Tabs>
  <Tab label="With attribute">
    ```csharp
    [GameEventHandler(HookMode.Pre)]
    public HookResult OnPlayerDeathPre(EventPlayerDeath @event)
    {
        Console.WriteLine($"victim={@event.UserId}, attacker={@event.Attacker}");
        return HookResult.Continue;
    }

    [GameEventHandler(HookMode.Post)]
    public HookResult OnPlayerDeathPost(EventPlayerDeath @event)
    {
        Console.WriteLine($"headshot={@event.Headshot}, weapon={@event.Weapon}");
        return HookResult.Continue;
    }
    ```

  </Tab>
  <Tab label="Programmatically">
    ```csharp
    private Guid _preHookId;

    public override void Load(bool hotReload)
    {
        _preHookId = Core.GameEvent.HookPre<EventPlayerDeath>(OnPlayerDeathPre);
    }

    public override void Unload()
    {
        Core.GameEvent.Unhook(_preHookId);
    }

    private HookResult OnPlayerDeathPre(EventPlayerDeath @event)
    {
        return HookResult.Continue;
    }
    ```

  </Tab>
</Tabs>

<ApiRef name="GameEventHandler" /> takes the mode in its constructor and the event type from the method's single parameter, and a method can carry only one (`AllowMultiple = false`). The attribute-based equivalents of `HookPre`/`HookPost` are discovered on the registered instances of your plugin - see [Using Attributes](/docs/development/using-attributes).

<Callout type="warning">
    In a pre hook, `HookResult.Stop` cancels the event and skips the remaining
    hooks; `HookResult.CancelOriginal` cancels it but still runs them, and
    `HookResult.Handled` skips them while letting the event through. `Stop` and
    `Handled` have no effect in post hooks.
</Callout>

Drop every hook registered for an event type at once:

```csharp
Core.GameEvent.UnhookPre<EventPlayerDeath>();
Core.GameEvent.UnhookPost<EventPlayerDeath>();
```

## Reading and Setting Event Data

Every generated event implements <ApiRef name="IGameEvent`1" />, giving you `Accessor` (<ApiRef name="IGameEventAccessor" />) and a settable `DontBroadcast` flag. Recognized fields get typed properties directly on the event - for `EventPlayerDeath`: `int UserId`/`Attacker`/`Assister`, `string Weapon`, `bool Headshot`, `float Distance`, `int ActualDmgHealth`, plus `IPlayer?` convenience wrappers (`UserIdPlayer`, `AttackerPlayer`, `AssisterPlayer`) resolved through the player manager:

```csharp
[GameEventHandler(HookMode.Post)]
private HookResult OnPlayerDeath(EventPlayerDeath @event)
{
    if (@event.AttackerPlayer is { } attacker && @event.UserIdPlayer is { } victim)
    {
        Console.WriteLine($"{attacker.Name} killed {victim.Name} with {@event.Weapon}");
    }

    return HookResult.Continue;
}
```

Fall back to `Accessor` for fields without a generated property - it reads and writes the raw payload fields by name (the same `DontBroadcast` flag sits on it too):

```csharp
string weapon = @event.Accessor.GetString("weapon");
int attackerSlot = @event.Accessor.GetPlayerSlot("attacker");

// e.g. in a pre hook, before the game processes the event
@event.Accessor.SetBool("headshot", true);
```

Every getter takes the field name, every setter the field name and the value:

| Getter / setter                                 | Payload type                  |
| ----------------------------------------------- | ----------------------------- |
| `GetBool` / `SetBool`                           | `bool`                        |
| `GetInt32` / `SetInt32`                         | `int`                         |
| `GetUInt64` / `SetUInt64`                       | `ulong`                       |
| `GetFloat` / `SetFloat`                         | `float`                       |
| `GetString` / `SetString`                       | `string`                      |
| `GetEntity<K>` / `SetEntity<K>`                 | entity, `K : CEntityInstance` |
| `GetEntityIndex` / `SetEntityIndex`             | `int`                         |
| `GetPlayerSlot` / `SetPlayerSlot`               | `int`                         |
| `GetPtr` / `SetPtr`                             | `nint`                        |

<ApiRef name="IGameEventAccessor" /> also exposes read-only helpers, resolved through the player manager: `GetPlayer(key)` (`IPlayer?`), `GetPlayerController(key)` (`CCSPlayerController`), `GetPlayerPawn(key)` (`CCSPlayerPawn`), `GetPawnEntityIndex(key)` (`int`), `IsReliable()` and `IsLocal()` (`bool`). Player references are stored as slots in the payload, which is why `userid`/`playerid` are read with `GetPlayerSlot`/`GetPlayer` (see [Terminologies](/docs/guides/terminologies)).

As a native wrapper, the accessor is also an <ApiRef name="INativeHandle" /> - `IsValid` and `Address` are available on it.

Check whether a slot is listening for an event with <ApiRef name="IGameEventService" member="IsListeningToEvent" /> - by event name (`"player_death"`) or the typed `IsListeningToEvent<EventPlayerDeath>(playerId)` overload.
