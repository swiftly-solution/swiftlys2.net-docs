title: Game Events
---

<Callout type="warning">
    Game events are a legacy Source 2 mechanism and Valve has been retiring them
    over time - some events no longer fire in current CS2 builds. Prefer [Game
    Hooks](/docs/development/native-functions-and-hooks) or [Core
    Events](/docs/development/core-events) when an equivalent exists.
</Callout>

SwiftlyS2 generates a strongly-typed interface for every CS2 game event, exposed through the plugin-scoped `Core.GameEvent` service (<ApiRef name="ISwiftlyCore" member="GameEvent" />, type <ApiRef name="IGameEventService" />). Every generated event implements <ApiRef name="IGameEvent`1" />, which gives it an `Accessor` property (<ApiRef name="IGameEventAccessor" />) and a settable `DontBroadcast` flag.

## Firing Events

Three targets, each with the same four members:

- `Fire<T>()` / `Fire<T>(Action<T>)` and `FireAsync<T>()` / `FireAsync<T>(Action<T>)` - broadcast to every player.
- `FireToPlayer<T>(int slot)` / `FireToPlayer<T>(int slot, Action<T>)` and their `FireToPlayerAsync` counterparts - a single player slot.
- `FireToServer<T>()` / `FireToServer<T>(Action<T>)` and their `FireToServerAsync` counterparts - server-side only.

The `Action<T>` overloads configure the event before it is sent, and every `Async` member returns `Task` for off-main-thread use - the sync members are marked `[ThreadUnsafe]`, see [Thread Safety](/docs/development/thread-safety).

```csharp
// To everyone, with an optional configure callback
Core.GameEvent.Fire<EventShowSurvivalRespawnStatus>(@event =>
{
    @event.LocToken = "survival_respawn_status";
    @event.Duration = 5;
});

// To one player slot
Core.GameEvent.FireToPlayer<EventShowSurvivalRespawnStatus>(0, @event =>
{
    @event.LocToken = "private_status";
});

// Server-side only
Core.GameEvent.FireToServer<EventShowSurvivalRespawnStatus>();

// Off the main thread
await Core.GameEvent.FireAsync<EventShowSurvivalRespawnStatus>();
```

<Callout type="warning">
    The event instance passed to a configure callback is only valid for that
    callback's duration - don't stash and read it later.
</Callout>

Every event has a settable `DontBroadcast` flag - set it inside the configure callback to build the event without broadcasting it to clients. The same flag is exposed on `IGameEventAccessor`.

## Hooking Events

Register hooks by attribute or manually through the service. The handler is the <ApiRef name="IGameEventService" member="GameEventHandler" /> delegate - `HookResult (T eventObj)`, with `T` constrained to `IGameEvent<T>` - and returns <ApiRef name="HookResult" />. Hooks run in `Pre` (`0`) or `Post` (`1`) mode (<ApiRef name="HookMode" />): `Pre` runs before the game processes the event, `Post` after.

- <ApiRef name="IGameEventService" member="HookPre" /> / <ApiRef name="IGameEventService" member="HookPost" /> take a `GameEventHandler<T>` and return a `Guid` identifying the hook.
- <ApiRef name="IGameEventService" member="Unhook" /> takes that `Guid` and removes the single hook.
- `UnhookPre<T>()` / `UnhookPost<T>()` drop every pre or post hook registered for one event type.

<Tabs>
  <Tab label="With attribute">
    ```csharp
    [GameEventHandler(HookMode.Pre)]
    public HookResult OnPlayerDeathPre(EventPlayerDeath @event)
    {
        Console.WriteLine($"victim={@event.UserId}, attacker={@event.Attacker}");
        return HookResult.Continue;
    }

    [GameEventHandler(HookMode.Post)]
    public HookResult OnPlayerDeathPost(EventPlayerDeath @event)
    {
        Console.WriteLine($"headshot={@event.Headshot}, weapon={@event.Weapon}");
        return HookResult.Continue;
    }
    ```

  </Tab>
  <Tab label="Programmatically">
    ```csharp
    private Guid _preHookId;

    public override void Load(bool hotReload)
    {
        _preHookId = Core.GameEvent.HookPre<EventPlayerDeath>(OnPlayerDeathPre);
    }

    public override void Unload()
    {
        Core.GameEvent.Unhook(_preHookId);
    }

    private HookResult OnPlayerDeathPre(EventPlayerDeath @event)
    {
        return HookResult.Continue;
    }
    ```

  </Tab>
</Tabs>

<ApiRef name="GameEventHandler" /> takes the mode in its constructor (`GameEventHandler(HookMode hookMode)`), exposes it as the settable `HookMode` property, and takes the event type from the method's single parameter - a method can carry only one (`AllowMultiple = false`). The attribute-based equivalents of `HookPre`/`HookPost` are discovered on the registered instances of your plugin - see [Using Attributes](/docs/development/using-attributes).

<Callout type="warning">
    In a pre hook, `HookResult.Stop` cancels the event and skips the remaining
    hooks; `HookResult.CancelOriginal` cancels it but still runs them, and
    `HookResult.Handled` skips them while letting the event through. `Stop` and
    `Handled` have no effect in post hooks.
</Callout>

Drop every hook registered for an event type at once:

```csharp
Core.GameEvent.UnhookPre<EventPlayerDeath>();
Core.GameEvent.UnhookPost<EventPlayerDeath>();
```

## Checking Event Listeners

<ApiRef name="IGameEventService" member="IsListeningToEvent" /> checks whether a player slot is listening for an event - by event name (`"player_death"`), or through the typed overload that takes the event type as a generic argument:

```csharp
bool byName = Core.GameEvent.IsListeningToEvent(0, "player_death");
bool typed = Core.GameEvent.IsListeningToEvent<EventPlayerDeath>(0);
```

## Reading and Setting Event Data

Recognized fields get typed properties directly on the event - for `EventPlayerDeath`: `int UserId`/`Attacker`/`Assister`, `string Weapon`, `bool Headshot`, `float Distance`, `int ActualDmgHealth`, plus `IPlayer?` convenience wrappers (`UserIdPlayer`, `AttackerPlayer`, `AssisterPlayer`) resolved through the player manager:

```csharp
[GameEventHandler(HookMode.Post)]
private HookResult OnPlayerDeath(EventPlayerDeath @event)
{
    if (@event.AttackerPlayer is { } attacker && @event.UserIdPlayer is { } victim)
    {
        Console.WriteLine($"{attacker.Name} killed {victim.Name} with {@event.Weapon}");
    }

    return HookResult.Continue;
}
```

Fall back to `Accessor` for fields without a generated property - it reads and writes the raw payload fields by name. Every getter takes the field name, every setter the field name and the value:

| Getter / setter                     | Payload type                  |
| ----------------------------------- | ----------------------------- |
| `GetBool` / `SetBool`               | `bool`                        |
| `GetInt32` / `SetInt32`             | `int`                         |
| `GetUInt64` / `SetUInt64`           | `ulong`                       |
| `GetFloat` / `SetFloat`             | `float`                       |
| `GetString` / `SetString`           | `string`                      |
| `GetEntity<K>` / `SetEntity<K>`     | entity, `K : CEntityInstance` |
| `GetEntityIndex` / `SetEntityIndex` | `int`                         |
| `GetPlayerSlot` / `SetPlayerSlot`   | `int`                         |
| `GetPtr` / `SetPtr`                 | `nint`                        |

```csharp
string weapon = @event.Accessor.GetString("weapon");
int attackerSlot = @event.Accessor.GetPlayerSlot("attacker");

// e.g. in a pre hook, before the game processes the event
@event.Accessor.SetBool("headshot", true);
```

<ApiRef name="IGameEventAccessor" /> also exposes read-only helpers, resolved through the player manager:

| Method                            | Returns               | Meaning                                           |
| --------------------------------- | --------------------- | ------------------------------------------------- |
| `GetPlayer(string key)`           | `IPlayer?`            | The player the field points at, or `null`         |
| `GetPlayerController(string key)` | `CCSPlayerController` | The player controller the field points at         |
| `GetPlayerPawn(string key)`       | `CCSPlayerPawn`       | The player pawn the field points at               |
| `GetPawnEntityIndex(string key)`  | `int`                 | The entity index of the pawn the field points at  |
| `IsReliable()`                    | `bool`                | Whether the event is marked as reliable           |
| `IsLocal()`                       | `bool`                | Whether the event is local to this server/client  |

Player references are stored as slots in the payload, which is why `userid`/`playerid` are read with `GetPlayerSlot`/`GetPlayer` (see [Terminologies](/docs/guides/terminologies)).

As a native wrapper, the accessor is also an <ApiRef name="INativeHandle" /> - `IsValid` and `Address` are available on it, next to the unsafe `DangerouslySetAddress(IntPtr address)`.

## Reference

Every event type on <ApiRef name="IGameEventService" /> is constrained to `where T : IGameEvent<T>`:

| Member               | Signature                                                                                                       | Returns                                 |
| -------------------- | --------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| `HookPre`            | `Guid HookPre<T>(GameEventHandler<T> callback)`                                                                  | the guid to pass to `Unhook`            |
| `HookPost`           | `Guid HookPost<T>(GameEventHandler<T> callback)`                                                                 | the guid to pass to `Unhook`            |
| `Unhook`             | `void Unhook(Guid guid)`                                                                                         | -                                       |
| `UnhookPre`          | `void UnhookPre<T>()`                                                                                            | -                                       |
| `UnhookPost`         | `void UnhookPost<T>()`                                                                                           | -                                       |
| `Fire`               | `void Fire<T>()` / `void Fire<T>(Action<T> configureEvent)`, `[ThreadUnsafe]`                                    | -                                       |
| `FireAsync`          | `Task FireAsync<T>()` / `Task FireAsync<T>(Action<T> configureEvent)`                                            | awaitable                               |
| `FireToPlayer`       | `void FireToPlayer<T>(int slot)` / `void FireToPlayer<T>(int slot, Action<T> configureEvent)`, `[ThreadUnsafe]`   | -                                       |
| `FireToPlayerAsync`  | `Task FireToPlayerAsync<T>(int slot)` / `Task FireToPlayerAsync<T>(int slot, Action<T> configureEvent)`           | awaitable                               |
| `FireToServer`       | `void FireToServer<T>()` / `void FireToServer<T>(Action<T> configureEvent)`, `[ThreadUnsafe]`                     | -                                       |
| `FireToServerAsync`  | `Task FireToServerAsync<T>()` / `Task FireToServerAsync<T>(Action<T> configureEvent)`                             | awaitable                               |
| `IsListeningToEvent` | `bool IsListeningToEvent(int slot, string eventName)` / `bool IsListeningToEvent<T>(int slot)`                    | whether that slot listens for the event |

The handler delegate is nested in the service: `GameEventHandler<T>` is `HookResult (T eventObj)`.

`IGameEvent<T>` itself only exposes `Accessor` (`IGameEventAccessor`, get-only) and the settable `DontBroadcast` (`bool`); its remaining members are internal to the framework.
