title: Translations
---

SwiftlyS2's translation APIs localize plugin text by key and automatically resolve player-specific language.

Text is read either from <ApiRef name="ISwiftlyCore" member="Localizer" /> (`Core.Localizer`, an <ApiRef name="ILocalizer" />) for server-wide lookups, or from <ApiRef name="ISwiftlyCore" member="Translation" /> (`Core.Translation`, an <ApiRef name="ITranslationService" />) when the text depends on the receiving player.

## Translation File Layout

Place `.jsonc` files named by language code under `resources/translations/` (for example `en.jsonc`, `fr.jsonc`, `pt-BR.jsonc`, `es-419.jsonc`). At least one must exist for the plugin's translations to load.

<Callout type="warning">
    Custom language codes work for direct lookups through `Core.Localizer`, but
    `Core.Translation.GetPlayerLocalizer(player)` only resolves the codes listed
    below.
</Callout>

<Callout type="info">
    Keep an `en.jsonc` baseline with all keys so unsupported or incomplete
    languages still have usable text.
</Callout>

## Example Translation File

```jsonc
{
    // General
    "plugin.name": "My Plugin",
    "plugin.ready": "Plugin is ready.",

    // Command feedback
    "command.heal.success": "You have been healed.",
    "command.heal.other": "{0} healed {1}",
    "command.heal.no_permission": "You do not have permission.",

    // Errors
    "error.player_not_found": "Player '{0}' was not found."
}
```

<Callout type="info">
    Values are chat-color-processed automatically, so `[red]`/`[green]`/etc.
    bracket syntax works directly inside translation strings. See [Chat &
    CenterHTML Styling](/docs/guides/chat-and-html-styling) for the full color
    list.
</Callout>

## Server-Side Localization

<ApiRef name="ILocalizer" /> is a read-only accessor for messages that aren't player-specific. It has no methods, only two indexers:

| Indexer | Returns | Description |
| --- | --- | --- |
| `this[string key]` | `string` | The translation stored under `key`. |
| `this[string key, params object[] args]` | `string` | The translation stored under `key`, formatted with `args`. |

The overload taking `args` formats the translation with `string.Format(string, object[])`, so `{0}`, `{1}`, ... placeholders and standard format specifiers work exactly as they do elsewhere in .NET - keep placeholder order stable across languages:

```csharp
string readyMessage = Core.Localizer["plugin.ready"];
string versionMessage = Core.Localizer["plugin.version", "1.2.0"];
string scoreMessage = Core.Localizer["plugin.score", player.Name, 1500, 0.75];
```

`Core.Localizer` is the <ApiRef name="ISwiftlyCore" member="Localizer" /> property, and an injected `ILocalizer` resolves to the same instance.

## Player-Specific Localization

<ApiRef name="ITranslationService" /> exposes a single member: <ApiRef name="ITranslationService" member="GetPlayerLocalizer" /> takes an <ApiRef name="IPlayer" /> and returns the <ApiRef name="ILocalizer" /> for that player, with the same two indexers as above. Use it when the output should match the player's language:

```csharp
public async Task GreetAsync(IPlayer player)
{
    var localizer = Core.Translation.GetPlayerLocalizer(player);
    string message = localizer["welcome.message", player.Name];

    await player.SendChatAsync(message);
}
```

`GetPlayerLocalizer` only returns a localizer - sending the text is up to you. The player-facing send methods on <ApiRef name="IPlayer" /> (`SendChat`/`SendChatAsync`, `SendCenter`/`SendCenterAsync`, `SendChatEOT`/`SendChatEOTAsync`, `SendAlert`/`SendAlertAsync`, `SendNotify`/`SendNotifyAsync`, `SendConsole`/`SendConsoleAsync` and `SendCenterHTML`/`SendCenterHTMLAsync`) all take the finished `string`.

### Broadcasting in Each Player's Language

<ApiRef name="IPlayerManagerService" member="SendMessage" /> and <ApiRef name="IPlayerManagerService" member="SendMessageAsync" /> also have overloads taking a <ApiRef name="MessageType" /> plus a `Func<IPlayer, ILocalizer, string>` callback instead of a fixed string. The callback receives the recipient and their localizer, so a single call builds the message per player in that player's own language:

```csharp
Core.PlayerManager.SendMessageAsync(MessageType.Chat, (player, localizer) =>
    localizer["plugin.welcome", player.Name]);

// the CenterHTML variants also take the display duration in milliseconds
Core.PlayerManager.SendMessageAsync(MessageType.CenterHTML, (player, localizer) =>
    localizer["plugin.countdown", 30], htmlDuration: 3000);
```

| Member | Callback Overload | Notes |
| --- | --- | --- |
| `SendMessage` | `(MessageType kind, Func<IPlayer, ILocalizer, string> messageCallback)` | `[ThreadUnsafe]` |
| `SendMessage` | `(MessageType kind, Func<IPlayer, ILocalizer, string> messageCallback, int htmlDuration = 5000)` | `[ThreadUnsafe]` |
| `SendMessageAsync` | `(MessageType kind, Func<IPlayer, ILocalizer, string> messageCallback)` | Returns `Task` |
| `SendMessageAsync` | `(MessageType kind, Func<IPlayer, ILocalizer, string> messageCallback, int htmlDuration = 5000)` | Returns `Task` |

Off the game thread, use the `Async` variants (or `Core.Scheduler`) - see [Thread Safety](/docs/development/thread-safety).

## The Language Type

<ApiRef name="IPlayer" member="PlayerLanguage" /> is a <ApiRef name="Language" /> value, which is handy for diagnostics or conditional flows:

```csharp
if (player.PlayerLanguage == Language.German)
{
    Core.Logger.LogInformation("German client: {SteamId}", player.SteamID);
}
```

<ApiRef name="Language" /> wraps a code string: `Value` is the code, `ToString()` returns it, and the type converts implicitly to `string`, so both of these hold the same code:

```csharp
string fromValue = player.PlayerLanguage.Value;
string fromConversion = player.PlayerLanguage;
```

Two <ApiRef name="Language" /> instances are equal when their codes are equal, and the type implements `IEquatable<Language>`. The static fields in the [Language Codes](#language-codes) table cover the codes listed there; the constructor is public, so `new Language("en")` builds the same value as `Language.English`.

<Callout type="info">
    `services.AddSwiftly(Core)` registers `Core.Localizer` and
    `Core.Translation` as singletons, so `ILocalizer` and
    `ITranslationService` can be constructor-injected - see [Dependency
    Injection](/docs/guides/dependency-injection).
</Callout>

## Key Design Best Practices

- Use stable dot-separated keys (for example `command.heal.success`).
- Keep the same key set across all language files.
- Add JSONC comments for translator context when placeholders are involved.
- Avoid string concatenation in code for translatable sentences.
