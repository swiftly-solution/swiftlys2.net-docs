---
title: Permissions
---

SwiftlyS2's permission service handles access checks, grant/revoke, and permission hierarchies.

## Accessing the Permission Service

Available through `Core.Permission` (<ApiRef name="ISwiftlyCore" member="Permission" />, type <ApiRef name="IPermissionManager" />). All checks and mutations key off SteamID64 (`ulong`) - use `player.SteamID`.

<Callout type="info">
    `services.AddSwiftly(Core)` registers `Core.Permission` as a singleton, so
    <ApiRef name="IPermissionManager" /> can be constructor-injected - see
    [Dependency Injection](/docs/guides/dependency-injection).
</Callout>

## Checking Permissions

<ApiRef name="IPermissionManager" member="PlayerHasPermission" /> takes `(ulong
steamId, string permission)` and checks one key;
<ApiRef name="IPermissionManager" member="PlayerHasPermissions" /> takes `(ulong
steamId, IEnumerable<string> permissions)` and requires every key in the list.
Both return `bool` and support `xxx.*` wildcard keys.

```csharp
if (Core.Permission.PlayerHasPermission(player.SteamID, "myplugin.admin"))
    player.SendChat("You have admin access.");

bool canUseRestrictedAction = Core.Permission.PlayerHasPermissions(
    player.SteamID,
    ["myplugin.admin.kick", "myplugin.admin.ban"]
);

bool isAdmin = Core.Permission.PlayerHasPermission(player.SteamID, "myplugin.admin.*"); // wildcard key
```

## Granting and Revoking Permissions

<ApiRef name="IPermissionManager" member="AddPermission" /> and
<ApiRef name="IPermissionManager" member="RemovePermission" /> each take a
`(ulong steamId, string permission)` pair;
<ApiRef name="IPermissionManager" member="ClearPermissions" /> takes only the
SteamID and clears all of the player's permissions, both base and temporary:

```csharp
Core.Permission.AddPermission(player.SteamID, "myplugin.vip");
Core.Permission.RemovePermission(player.SteamID, "myplugin.vip");
Core.Permission.ClearPermissions(player.SteamID); // clears both base and temporary permissions
```

<Callout type="warning">
    `ClearPermission` (singular) is obsolete, forwarding to `ClearPermissions` -
    use the plural in new code.
</Callout>

## Listing a Player's Permissions

<ApiRef name="IPermissionManager" member="GetPlayerPermissions" /> takes the
`ulong steamId` and returns an `IEnumerable<string>` of everything the player
effectively has, including permissions inherited from sub-permissions.

```csharp
IEnumerable<string> permissions = Core.Permission.GetPlayerPermissions(player.SteamID);
```

## Sub-Permissions (Hierarchy)

One permission key can imply another: <ApiRef name="IPermissionManager"
member="AddSubPermission" /> takes `(string permission, string subPermission)`
and records that `permission` also grants `subPermission`. Both hierarchy
members take only the two keys, because the hierarchy is defined for the
permission keys themselves rather than per player.

```csharp
Core.Permission.AddSubPermission("myplugin.admin", "myplugin.moderator");

Core.Permission.AddPermission(player.SteamID, "myplugin.admin");

bool isModerator = Core.Permission.PlayerHasPermission(player.SteamID, "myplugin.moderator"); // true, inherited from myplugin.admin
```

Remove an edge with <ApiRef name="IPermissionManager" member="RemoveSubPermission" />, which takes the same pair:

```csharp
Core.Permission.RemoveSubPermission("myplugin.admin", "myplugin.moderator");
```

## Permission Naming Convention

A consistent `plugin.scope.action` scheme keeps wildcards and hierarchies predictable, e.g. `myplugin.admin.kick`, `myplugin.admin.ban`, `myplugin.vip.access`, `myplugin.commands.reload`.

## Using Permissions with Commands

<ApiRef name="Command" />
's `permission` parameter checks this same store, so you rarely need
<ApiRef name="IPermissionManager" member="PlayerHasPermission" /> directly
inside a handler:

```csharp
[Command("ban", permission: "myplugin.admin.ban")]
public void OnBanCommand(ICommandContext context)
{
    // Only reached if context.Sender has "myplugin.admin.ban"
}
```

See the [Commands](/docs/development/commands) page for the full attribute reference.
