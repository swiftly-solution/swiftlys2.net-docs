---
title: CLI Options
---

SwiftlyS2 startup behavior can be configured with command-line options passed when launching the game server.

## Startup Example

```bash
./game/bin/win64/cs2.exe -dedicated +map de_dust2 \
	-sw_path addons/swiftlys2 \
	-sw_logpath addons/swiftlys2/logs \
	-sw_hide_logs_in_console 1 \
	-sw_loglevel WARNING
```

## Options Reference

| Option                     | Example                             | Details                                                                                                                                   |
| -------------------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `-sw_path`                 | `-sw_path addons/swiftlys2`         | Relative path from `game/csgo` where SwiftlyS2 is installed. Default: `addons/swiftlys2`.                                                  |
| `-sw_logpath`              | `-sw_logpath addons/swiftlys2/logs` | Relative path where managed (.NET) plugin logs are written. Default: `addons/swiftlys2/logs`.                                              |
| `-sw_hide_logs_in_console` | `-sw_hide_logs_in_console 1`        | Hides managed plugin logs in console; they are still written to files. Accepted values: `1`, `TRUE`, `YES`.                                 |
| `-sw_loglevel`             | `-sw_loglevel WARNING`              | Minimum log level for console output. Default: `INFO`. Accepted values: `TRACE`, `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`, `NONE`. |

## Notes

- `-sw_path` and `-sw_logpath` are relative to the `game/csgo` directory, and a trailing slash is added automatically.
- Every occurrence of `addons/swiftlys2` in `-sw_logpath` is replaced with the value of `-sw_path`, so the default log directory follows a custom `-sw_path`. A value that does not contain `addons/swiftlys2` is used as-is.
- `-sw_logpath` only affects managed (.NET) plugin logs; console logs are always written to `logs/console/` inside the `-sw_path` directory. Log rotation is configured through `ConsoleLogger` - see [Core Configuration](/docs/resources/core-config).
- Use `-sw_hide_logs_in_console` when you want plugin logs to remain in files but not in console output. Logs from the `Core` and `Shared` categories are still printed, and passing the option without one of the accepted values does not enable it.
- Use `-sw_loglevel` to reduce console noise while preserving higher-severity logs. Values are case-insensitive and unrecognized values fall back to `INFO`. The native logger accepts the full list above, while the managed (.NET) logger only understands `DEBUG`, `INFO`, `WARNING`, `ERROR` and `OFF` and falls back to `INFO` for anything else.
- All four options are read once when the core loads: `-sw_loglevel` sets `SWIFTLY_LOG_LEVEL` and `-sw_hide_logs_in_console` sets `SWIFTLY_HIDE_LOG_IN_CONSOLE`.
